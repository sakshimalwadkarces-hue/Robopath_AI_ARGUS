# Team Working Rules

1. Define the result expected today before opening code.
2. Assign one accountable owner to every task; collaboration is still welcome.
3. Record every external source in the research log before relying on it.
4. Keep raw inputs immutable. Put transformations in scripts or notebooks.
5. Use member workspaces for experimentation and shared integration for reviewed work.
6. A result without a file, commit, screenshot, test or link is not complete evidence.
7. Update the individual diary and shared group diary every working day.
8. Discuss architecture, dataset, algorithm, metric and deployment changes with the group.
9. Never place secrets or personal data in Git.
10. Keep `main` reproducible and presentation-ready.

## Definition of done

- The output satisfies its acceptance condition.
- Another member can locate and run or inspect it.
- Relevant test or review evidence exists.
- Source, decision and limitation notes are updated.
- The task and diary reflect the actual result.
